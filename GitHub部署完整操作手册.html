0先回答你问过的两个问题

Q1：为什么必须公开？

GitHub 免费账号只有「公开（Public）」仓库才能用 Pages 网页托管，私有仓库的 Pages 是付费功能。 页面要挂到网上让手机访问，免费路线只能是公开仓库。

公开的是仓库文件，不是你的账号：

内容是否公开说明
网页代码、抓到的动态、照片公开本来就是公开内容
微博登录 Cookie不公开存在「机密（Secrets）」里，加密保存，谁都看不到原文
微信推送 Key（以后再加）不公开同样存在机密里
你的微博密码不涉及只用了浏览器里的登录状态，从没碰过密码
唯一一条硬性规则：Cookie 绝不能明文进仓库。它只能放在「机密」里。 已用 .gitignore 兜底，实测待提交清单里没有 cookies.json。
Q2：微信推送现在不要，以后能加吗？

能，3 分钟，不用改代码。推送已写进采集脚本，现在只是没给它钥匙，所以静默不动。

  1. 打开 sct.ftqq.com，微信扫码登录，复制 SendKey（SCT 开头）
  2. 仓库 → 设置（Settings） → 机密和变量（Secrets and variables） → 操作（Actions） → 新建一条：名称填 SENDKEY，值粘贴那串 Key

保存即生效。现在你只需要填一条机密：WEIBO_COOKIE。

1注册 / 登录 GitHub（已有账号跳过）

① 打开 github.com → 右上角 注册（Sign up） → 邮箱注册 → 去邮箱点验证链接
如果界面是英文，认准右上角的 Sign up / Sign in
② 登录后：右上角头像 → 设置（Settings） → 左侧 电子邮件（Emails）， 确认邮箱已验证（没验证后面会推送失败） 🔗 打开页面

2新建仓库（存储库）

🔗 直接打开新建仓库页
① 也可以点右上角 + → 新建仓库（New repository）
② 仓库名称（Repository name） 填 starhub
③ 描述（Description） 随便写一句；下面选 公开（Public）
公开 = Public　私有 = Private，别选错
④ 页面下方三个选项 全部不要勾（不要 README、不要 .gitignore、不要 license）—— 我们本地已经有了，勾了会和本地文件冲突导致推送失败
⑤ 点 创建仓库（Create repository）
⑥ 建好后页面中间会显示仓库地址，形如
https://github.com/你的用户名/starhub.git
复制保存好，第 4 步要用。

3生成 Token（个人访问令牌）

⚠️ 注意有两个「Settings」，别走错：你现在在的是「仓库的设置」（网址是 github.com/用户名/starhub/settings）。 Developer settings 藏在「账号的设置」里——点页面最右上角你的头像，菜单里那个 Settings。 搞不清就直接点下面的链接。

🔗 直接打开令牌页（推荐）

推送代码到 GitHub 现在不能用密码，必须用这个令牌。

① 注意走的是账号设置：右上角头像 → 设置（Settings） （不是仓库里的 Settings！）→ 左侧最下方 开发者设置（Developer settings） → 个人访问令牌（Personal access tokens） → 令牌（经典）（Tokens (classic)）
② 点 生成新令牌（经典）（Generate new token (classic)）
③ 备注（Note） 随便填，比如 starhub
④ 有效期（Expiration） 选 90 days（90 天） 或 No expiration（无期限）
⑤ 权限勾选（关键，认准这两个英文单词）：
  • ✅ repo（中文界面显示的就是 repo，勾上会自动带上下面子项）
  • ✅ workflow（不勾这个，定时任务的那个文件推不上去）
⑥ 拉到最下面点 生成令牌（Generate token）
⑦ 立刻复制那串绿色令牌（ghp_ 开头）并保存。离开这页就再也看不到，只能重新生成。

4电脑上跑三个脚本

打开文件夹 starhub → 云部署工具，按顺序双击：

① 1_初始化本地仓库.bat
  • 第一次运行会让你输一次邮箱，填 GitHub 的邮箱即可
  • 会列出要提交的文件，确认里面没有 data/cookies.json 和 browser-profile 再按任意键继续
  • 看到「本地仓库准备好了」就成功
② 2_导出Cookie到剪贴板.bat
  • 会后台开一次浏览器（约 10 秒）读微博登录状态
  • 提示「Cookie 已复制到剪贴板」——先别急，第 5 步才粘贴
③ 3_推送到GitHub.bat
  • 依次问三件事，粘贴后回车：仓库地址 / GitHub 用户名 / 令牌
  • 看到「推送成功！」就完成上传
cmd 窗口里用 鼠标右键粘贴（Ctrl+V 有时不灵）。输入令牌时屏幕不显示字符是正常的，直接回车。

5回 GitHub 完成三处设置

① 填入微博 Cookie（最重要） 🔗 打开机密页面
  • 仓库页面 → 设置（Settings） → 左侧 机密和变量（Secrets and variables） → 操作（Actions）
  • 点 新建仓库机密（New repository secret）
  • 名称（Name） 填：WEIBO_COOKIE（全大写，一字不差）
  • 下面大框里 Ctrl+V 粘贴第 4 步复制的 Cookie → 点 添加机密（Add secret）
② 打开工作流的写权限 🔗 打开 Actions 设置
  • 仓库页面 → 设置（Settings） → 操作（Actions） → 常规（General）
  • 拉到最下方 工作流权限（Workflow permissions）
  • 选 读取和写入权限（Read and write permissions） → 保存（Save）
  • 不改的话，定时任务抓到新帖也写不回仓库
③ 开启 Pages 网页托管 🔗 打开 Pages 设置
  • 仓库页面 → 设置（Settings） → 左侧 页面（Pages）
  • 源（Source） 选 从分支部署（Deploy from a branch）
  • 分支（Branch） 选 main，目录选 / (root)（根目录） → 保存（Save）
  • 等 1～2 分钟，页面顶部会出现你的网址
到这一步云端就活了。打开网址能看到星汇页面，显示真实微博动态。

6手机上使用

① 手机浏览器打开 https://你的用户名.github.io/starhub/
② iPhone：Safari 底部「分享」→「添加到主屏幕」
安卓：Chrome 右上角菜单 →「添加到主屏幕 / 安装应用」
数据怎么更新：GitHub 每 10 分钟自动抓微博 → 有新帖写回仓库 → 网页 1～2 分钟同步 → 你打开 App 时它每 60 秒检查一次。全程不需要电脑开机。

7维护与常见问题

Cookie 过期（最常见）

表现：内容一直是旧的 → 去 操作（Actions） 页看到红色失败圆圈，日志写「非 JSON 响应（Cookie 可能已过期）」

🔗 打开 Actions 运行记录

处理：重跑 2_导出Cookie到剪贴板.bat → 设置 → 机密和变量 → 操作 → 点 WEIBO_COOKIE → 更新（Update secret） → 粘贴新的 → 保存。立刻生效。

想立刻抓一次

仓库 → 操作（Actions） → 左侧点「星汇定时采集」→ 右侧 运行工作流（Run workflow） → 再点一次。约 30 秒跑完。

页面显示「未连接采集服务 / 内置数据」

  • 确认页面（Pages）已开启并显示网址（首次要等 1～2 分钟）
  • 确认仓库里 data/posts.json 存在
  • 手机下拉强制刷新一次

定时任务自己停了

GitHub 规定仓库连续 60 天无提交会停用定时任务。我们每次采集都留一条记录，基本不会触发。 万一停了，去操作（Actions）页手动运行一次就恢复。

中英文对不上怎么办

GitHub 中文版翻译并不完整，很多地方仍是英文，属于正常现象。认准括号里的英文单词最保险， 或者直接点本手册里的「🔗 打开页面」直达链接。
